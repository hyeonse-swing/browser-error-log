# 자체 백엔드 계약

[English](../server-request.md) | 한국어

포함된 [마이크로 서버](micro-server.md)가 로컬 영속 저장의 가장 짧은 경로입니다. 다른 DB, 별도 백엔드, 기존 서비스 인증이 필요하면 이 문서를 사용하세요. 현재 [v1 SDK·뷰어 계약](integration.md)에 맞춘 구현 책임을 설명하며 운영 백엔드가 이미 배포되었다는 뜻은 아닙니다.

## 현재 뷰어에 필요한 기능

`packages/protocol`의 v1 `EventBatch`로 `POST /api/events`를 받습니다. 저장 전에 잘못된 배치를 거절하고 요청 크기·이벤트 수·속도를 제한하세요. 클라이언트가 보낸 project, Origin, 시각을 신뢰하지 마세요. `(project, eventId)`로 저장해 재시도 중복을 막습니다. 전체 배치가 영속 저장되거나 기존 중복으로 확인된 뒤에만 2xx를 반환하세요. SDK는 429·5xx를 재시도하고 다른 4xx는 종료합니다. 일부만 성공할 수 있다면 SDK가 배치 단위로 재시도하므로 멱등성을 유지해야 합니다.

```text
GET /api/events?project=...&environment=...&type=...&query=...&from=...&to=...&cursor=...&limit=30
GET /api/events/:eventId?project=...
```

목록은 `{ "events": [...], "nextCursor": "opaque-cursor-if-more" }`, 상세는 이벤트 또는 404를 반환합니다. 안정적인 동률 정렬을 포함해 최신순으로 정렬하고 새 이벤트가 와도 커서 경계를 유지하세요. 조회는 호출자에게 허용된 프로젝트로 제한합니다. `packages/protocol`의 `EventDataSource`가 뷰어 측 인터페이스입니다. 같은 Origin의 API는 [연동 계약](integration.md)의 `window.__ERROR_LOG_VIEWER_CONFIG__`로 지정할 수 있습니다. 다른 Origin의 뷰어에는 별도의 CORS·인증 설계가 필요합니다.

## 운영자 책임

- 보관·삭제 정책, 디스크/DB 용량, 백업, 복구 시험을 정합니다. 예제의 7일/10,000건은 모든 서비스에 적용되는 필수값이 아닙니다.
- 뷰어와 조회 API의 접근을 보호합니다. 브라우저 `project`·`Origin` 확인은 신원 증명이 아닙니다. 장기 서버 비밀을 브라우저 코드에 넣지 마세요.
- SDK의 `sanitizeUrl`·`beforeSend`를 설정해도 URL 경로, 메시지, 스택, `context`의 앱별 식별자를 검증하거나 제거합니다. 자동 마스킹은 완전하지 않습니다.
- 배치와 요청 속도를 제한하고 저장 오류를 처리합니다. 오프라인, 탭 종료, 재시도 소진으로 기록이 유실될 수 있습니다. 통제된 이벤트의 수신·저장·목록·상세·삭제·복원을 시험하세요.
- 클라이언트 발생 시각과 서버 수신 시각을 구분합니다. 클라이언트 시계가 틀릴 수 있다면 보관 기준은 수신 시각을 사용하세요.

단일 호스트의 작은 배포라면 포함된 SQLite 구현이 이 계약의 제한된 버전을 제공합니다. JSONL은 수신과 오프라인 내보내기만 지원하며 목록·상세 API는 `501`입니다. 로컬 개발 수집기는 메모리를 사용하고 재시작하면 기록이 사라집니다.

## 향후 확장

현재 뷰어는 최대 100페이지·고유 이벤트 10,000건을 가져와 로컬에서 차트를 계산하고 상한에 닿으면 부분 결과로 표시합니다. 더 큰 저장 범위의 완전한 건수가 필요하면 이벤트 조회와 같은 필터·권한·보관 경계로 서버 집계 API와 뷰어를 함께 설계하세요. 소스맵 업로드·복원, 이슈 묶음, 알림, 운영 흐름은 현재 API가 아닌 [로드맵](expansion-roadmap.md) 범위입니다.

인프라는 포함되지 않습니다. 호스팅, 서버, 데이터베이스, 스토리지, 대역폭, 도메인, 백업 및 제3자 서비스는 각 운영자가 선택하고 비용을 부담합니다. 요금은 해당 제공업체가 이 프로젝트 및 유지관리자와 독립적으로 청구합니다.
