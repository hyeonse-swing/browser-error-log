# 프로젝트 로드맵

[English](../expansion-roadmap.md) | 한국어

공개 프로젝트의 가능한 개선 방향입니다. 배포, 출시일, 제공업체 선택, 기능 구현 약속이 아닙니다. 현재 동작은 [README](../../README.ko.md), [SDK 가이드](personal-sdk.md), [마이크로 서버 가이드](micro-server.md), [v1 계약](integration.md)에 있습니다.

## 현재 기준

브라우저 SDK는 전역 JavaScript 예외, 미처리 Promise, fetch/XHR 실패, 선택한 HTTP 응답, 수동 오류를 수집합니다. 버퍼·시도별 시간·재시도에 상한이 있습니다. 선택적인 React 어댑터는 렌더링 오류를 잡습니다. 뷰어는 필터·타임라인·상세·가져온 기록의 차트·로컬 JSON 입출력을 제공합니다. 단일 프로세스 마이크로 서버는 SQLite 또는 회전 JSONL 파일에 저장합니다. 개발용 데모 수집기는 메모리만 사용합니다.

MIT 라이선스 `0.1.0` 브라우저 SDK, React 어댑터, 프로토콜 패키지는 npm에 게시되었습니다. 다국어 지원 `0.1.1`은 게시 준비 중입니다. 소스는 GitHub 저장소에 있으며 npm 게시와 GitHub 릴리스·태그는 별개입니다. 검증과 향후 릴리스 절차는 [릴리스 가이드](releasing.md)에 있습니다.

SQLite 기본값은 수신 후 7일, 10,000건, DB 본체 64 MiB입니다. JSONL은 8 MiB 파일 3개가 기본이며 온라인 조회 API는 없습니다. 뷰어 분석은 100페이지·고유 이벤트 10,000건으로 제한하며 상한에 닿은 결과는 부분 결과입니다. 이 기본값은 작은 시작점을 제공하지만 완전한 수집이나 모든 부하에 대한 적합성을 보장하지 않습니다.

## 다음 결정과 후보 작업

| 영역 | 후보 작업 | 검토 이유 |
| --- | --- | --- |
| SDK 신뢰성 | 반복 오류 제한, 유실 사유 구분, 지원 브라우저·WebView 검증 | 대량 오류 상황을 이해하기 쉽게 함 |
| 개인정보 제어 | 앱별 필터 시험과 서버 제거 지점 문서화 | 경로·메시지·스택·context의 식별자 수집 감소 |
| 진단 | 비공개 소스맵 처리와 신중한 오류 묶음 | 배포 스택을 원본 코드에 연결하고 별개 원인을 숨기지 않음 |
| 큰 데이터 | 조회와 같은 필터·권한의 서버 집계 | 뷰어 조회 상한 이후에도 완전한 건수 표시 |
| 운영 | 복구 연습, 백업, 접근 검토, 선택적 알림·이슈 흐름 | 더 긴 보관이나 대응 절차 지원 |

각 확장에는 구현·문서·실제 배포 환경의 검증이 필요합니다. 현재 SQLite 서버는 이 기능을 기다리지 않고 사용할 수 있습니다. 자체 백엔드는 [계약](server-request.md)에 맞춰 별도 저장소와 권한 설계를 적용할 수 있습니다.

현재 제외 범위는 세션 리플레이, 네이티브 앱 크래시, 보장된 또는 정확히 한 번의 브라우저 전달, 소스맵 자동화, 알림, 서버 전체 집계입니다. 기본 URL 마스킹은 최선형이며 앱별 개인정보 검토를 대신하지 않습니다. 차트는 수집 이벤트 건수이며 사용자 수나 전체 요청 대비 오류율이 아닙니다.

인프라는 포함되지 않습니다. 호스팅, 서버, 데이터베이스, 스토리지, 대역폭, 도메인, 백업 및 제3자 서비스는 각 운영자가 선택하고 비용을 부담합니다. 요금은 해당 제공업체가 이 프로젝트 및 유지관리자와 독립적으로 청구합니다.
